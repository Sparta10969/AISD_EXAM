## Билет 1 Методологии программирования. Понятие алгоритма. Способы записи алгоритмов.

Методологии
	
1. Хаотическое – написание кода без предварительного проектирования.

2. Структурное – использование последовательности, ветвлений, циклов; отказ от goto.

3. Объектно-ориентированное (ООП) – инкапсуляция, наследование, полиморфизм, абстракция (кто питон учил, те запомнили уже)

Понятие алгоритма
	
• Формула Вирта: Программа = Алгоритм + Данные

• Определение: корректно определённая вычислительная процедура, на вход которой подаётся величина (или набор), а результатом является выходная величина (или набор).

• Схема: Входные данные → [Алгоритм] → Выходные данные

• Пример: задача сортировки {a₁...aₙ} → {a₁'≤a₂'≤...≤aₙ'}

Эффективность
	
t = k / v, где k – количество операций, v – быстродействие процессора.

Сравнение:
• Вставками: k₁ = c₁·n², c₁=2, v₁=10⁹ → при n=10⁹ ≈ 2000 сек
• Слиянием: k₂ = c₂·n·log₂n, c₂=50, v₂=10⁷ → при n=10 ≈ 2,3 дня

Способы записи
	
1. Словесное описание
2. Схема алгоритма (блок-схема)
3. Псевдокод
4. Программа на ЯП

## Билет 6. Элементарные структуры данных: стек и очередь, представленные списком.

 Очередь (FIFO) - first int first out

    Динамическая структура с двумя концами (голова head, хвост tail).

    Реализация на векторе (циклический буфер):
        Пуста: head == tail (или n == 0)
        Запись: queue[tail] = info; tail = (tail + 1) % N
        Полна: head == tail (или n == N)
        Чтение: info = queue[head]; head = (head + 1) % N

    Использование % N позволяет эффективно переиспользовать освободившиеся ячейки без сдвигов.
    N- размер очереди

Стек на списке

    Вставка/извлечение всегда с головы (top).
    Push: x->next = top; top = x;
    Pop: x = top; top = top->next; x->next = NULL;
    Сложность: O(1), без необходимости сдвига памяти.

Очередь на линейном списке

    Вставка в хвост (tail), извлечение из головы (head).
    Пустая: head = NULL, tail = NULL

Очередь на циклическом списке

    Используется один указатель tail. Начало очереди: head = tail->next.

Преимущество: постоянный доступ к обоим концам за O(1), экономия памяти (один указатель вместо двух)

## Билет 7. Таблицы: основные определения, классификация таблиц, способы отображения в памяти.

1. Определение

Таблица — это динамическое множество элементов, каждый из которых состоит из пары (Ключ, Информация).

    Ключ key — уникальное значение, идентифицирующее элемент.

    Информация  info — сопутствующие данные.

2. Основные операции

    Поиск (Search): найти элемент по ключу.

    Вставка (Insert): добавить новый элемент (если ключа нет).

    Удаление (Delete): убрать элемент по ключу.

3. Классификация таблиц


    Просматриваемые (неупорядоченные): элементы хранятся в порядке поступления, поиск только линейный.

    Упорядоченные: элементы отсортированы по ключу, возможен бинарный поиск.

    С вычисляемым входом (Хеш-таблицы): 
    
    адрес вычисляется функцией h(k).

        Прямая адресация: r(k) уникальна для каждого ключа.

        Перемешанные (Hash): возможны коллизии.

    Произвольного доступа: прямой доступ по индексу (массив).

4. Отображение в памяти (Слайды 3.4–3.7)

    Вектор (массив): непрерывная область памяти. Доступ по индексу O(1)

    Список: элементы связаны указателями. Доступ последовательный.

    Сеть: произвольные связи (граф).

## Билет 8. Просматриваемая таблица – вектор: определение, основные операции, особенности их реализации.

Суть: Элементы не сортируются. Хранятся в массиве.
Операции и реализации 

    Поиск (Search):
        Линейный просмотр от 0 до n−1
        Сложность: Θ(n).
    Вставка (Insert):
        Сначала Search (чтобы не было дубликатов).
        Если места нет → отказ.
        Иначе запись в конец: table[n] = new_elem, n = n + 1.
        Сложность: Θ(n) (доминирует поиск).
    Удаление (Delete):
        Найти элемент (индекс i).
        Заменить его последним элементом таблицы: table[i] = table[n-1].

        Уменьшить размер: n = n - 1.

        Важно: Порядок элементов нарушается, но это допустимо для просматриваемой таблицы.

        Сложность: Θ(n)

## Билет 10. Упорядоченная таблица: определение, основные операции, особенности их реализации.

Суть: Ключи всегда отсортированы (k1<k2<⋯<kn)

Операции 

    Поиск:
        Бинарный поиск (деление отрезка пополам).
        Сложность: Θ(log⁡2 n)
    Вставка:

        Сложность: Θ(n).

Таблицы с вычисляемым входом - это таблицы, когда фукнция расстановки просто есть

    Коэффициент заполнения: σ=n/m<1
    Эффективность:
        Поиск, Вставка, Удаление выполняются за  O(1).

    Минус: Если множество ключей U велико, а активных элементов n мало, память расходуется неэффективно (много пустых ячеек).

## Билет 13: Хеш-таблица с перемешиванием сцеплением (Chaining)

Суть: Таблица — это массив указателей на головы связных списков (цепочек).

Открытая таблица с закрытой адресацией

Операции

    Вставка:
        Вычислить idx=h(k)
        Проверить, нет ли ключа в списке table[idx].
        Добавить элемент в начало списка table[idx].
    Поиск:
        Вычислить idx=h(k)
        idx=h(k).
        Линейный поиск в списке table[idx].
    Удаление:
        Найти элемент в списке table[idx] и удалить узел.

Оценка эффективности 

    Коэффициент заполнения: σ=n/m (средняя длина цепочки).
    Средний случай: Θ(1+σ)
    Худший случай: Θ(n) (все ключи попали в одну цепочку).

## Билет 14: Хеш-таблицы с открытой адресацией
Суть: Все элементы хранятся непосредственно в ячейках массива таблицы. Списков нет.

Основные понятия 

    Последовательность исследований: h(k,0),h(k,1),
    h(k,0),h(k,1),— это перестановка индексов 0..m−1

    Статусы ячеек или поле busy
        FREE (0) — ячейка никогда не использовалась.
        OCCUPIED (1) — ячейка занята.
        DELETED (2) — ячейка была занята, но элемент удален.

Особенности 

    Поиск: останавливается при встрече FREE. DELETED пропускает.

    Вставка: может использовать ячейки со статусом DELETED или FREE. Лучще запоминать обе, потому что при поиске мы обязаны дойти до конца и их сравнивать, чтобы вставить в ближайшую (Овчаренко подшар)

    Удаление: нельзя ставить статус FREE (это разорвет цепочку пробирования для других элементов). Ставится статус DELETED.

## Билет 16: Хеш-таблица: квадратичное исследование, двойное хеширование. Оценка эффективности.

1. Квадратичное исследование (Quadratic Probing)

Это метод разрешения коллизий в открытой адресации, при котором расстояние между следующими проверяемыми ячейками растет квадратично.
Хеш-функция:
```
h(k,i)=(h′(k)+c1⋅i+c2⋅i^2)(mod m)

    k — ключ.
    i — номер исследования (пробирования), i=0,1,2, ...

    h′(k) — вспомогательная хеш-функция (базовая позиция).

    m — размер таблицы.

    c1​,c2​ — вспомогательные константы c1,c2≠0
```

Особенности:

    Позволяет избежать первичной кластеризации (когда блоки занятых ячеек сливаются в длинные цепочки, как при линейном пробировании).
    Ограничения: Для того чтобы последовательность проб была перестановкой 0,…,m−1  (т.е. чтобы алгоритм гарантированно нашел свободное место, если оно есть), требуется выбор специальных значений c1,c2 и m
    m выбирают простым числом, а константы так, чтобы покрыть хотя бы половину таблицы.

2. Двойное хеширование (Double Hashing)

Один из лучших методов открытой адресации. Использует две хеш-функции.
Хеш-функция:
```
h(k,i)=(h1(k)+i⋅h2(k))(modm)

    h1​(k) — основная хеш-функция (определяет начальную позицию).
    h2​(k) — вторая хеш-функция (определяет шаг смещения).
    i — номер попытки.
```

Ключевые требования:

    Значение h2(k)
    h2​(k) должно быть взаимно простым с размером таблицы m.
        Вариант реализации: 
        m — простое число, а h2(k)
        h2​(k) возвращает натуральные числа, меньшие m (например, 1≤h2(k)<m1).
    Это гарантирует, что последовательность исследования будет перестановкой всех индексов таблицы 0,…,m−11

Преимущество:

    Минимизирует как первичную, так и вторичную кластеризацию. Элементы с разными ключами будут "прыгать" по таблице с совершенно разными шагами.

3. Оценка эффективности

Эффективность хеш-таблиц с открытой адресацией зависит от коэффициента заполнения:
```
σ=n/m
```
где
n — количество элементов,
m — размер массива.
Предполагается равномерное хеширование (все элементы отображаются на ячейки независимо и равновероятно).

    Удаление:

## Билет 18 Деревья: определение, разновидности деревьев. Представление произвольного дерева с помощью двоичного дерева. Операции обхода дерева.

Определение и разновидности

    Дерево – множество вершин, которое либо пусто, либо состоит из корня и совокупности связанных с ним поддеревьев. Каждое поддерево само является деревом. 
    Разновидности:

        N-арное (произвольное): узел хранит массив указателей Node* ptrs[N] или динамический массив Node** ptrs. 

        Двоичное: корень + левое поддерево + правое поддерево. 

Представление произвольного дерева двоичным.

Используется схема «Левый ребёнок – Правый брат» :

    Поле left узла указывает на его самого левого дочернего узла.
    Поле right узла указывает на следующего брата (соседний дочерний узел того же родителя).
    Позволяет хранить дерево любой степени в памяти, используя стандартную структуру бинарного дерева.

## Билет 19. Бинарные деревья поиска: определение, обход дерева, операции поиска. Поиск по ключу, минимума и максимума. Оценки эффективности.

BST – дерево, где для любой вершины x с ключом k_x:

    Все ключи в левом поддеревье Л[x] ≤ k_x
    Все ключи в правом поддеревье П[x] ≥ k_x
    Каждая вершина помечена отдельным ключом. 

Обход и поиск

    Центрированный обход BST выдаёт ключи в строго возрастающем порядке. 

    Поиск по ключу: сравниваем с текущим узлом. Если < → влево, если > → вправо, если == → успех. Дошли до NULL → отказ. 

    Поиск минимума: двигаться по указателям left до NULL. 

    Поиск максимума: двигаться по указателям right до NULL. 

Оценка эффективности

Все операции поиска выполняются за Θ(h), где h – высота дерева.

    Худший случай: дерево вырождено в список → h = n → Θ(n).

    Средний/оптимальный случай: сбалансировано → h ≈ log₂n → Θ(log n). 

## Билет 20. Бинарные деревья поиска: поиск предшествующего и последующего элементов. Оценки эффективности.

Определения

    Предшествующий (predecessor): элемент с наибольшим ключом < данного.

    Последующий (successor): элемент с наименьшим ключом > данного.

    Соответствуют соседям в последовательности центрированного обхода. 

Алгоритм поиска последующего (требует поле parent)

    Если есть правое поддерево: последующий = минимум правого поддерева (спуск влево до конца).

    Если правого поддерева нет: поднимаемся вверх по родителям, пока текущий узел не станет левым ребёнком своего родителя. Родитель этого узла и будет последующим.

    Если дошли до корня и не нашли → последующего нет (NULL). 

(Поиск предшествующего симметричен: если есть левое → максимум левого, иначе подъём вверх, пока узел не станет правым ребёнком.)

Оценка эффективности

В худшем случае Θ(n), в сбалансированном Θ(log n).

## Билет 21. Бинарные деревья поиска: вставка нового элемента. Оценки эффективности.

Алгоритм вставки

    Если дерево пусто (root == NULL) → новый элемент становится корнем.

    Иначе ищем позицию вставки, двигаясь от корня (как при поиске):

        Запоминаем текущего (cur) и его родителя (par).
        Если key_new < cur->key, тогда cur = cur->left, иначе cur = cur->right.

    Когда cur == NULL, присоединяем новый узел к par как левое или правое поддерево.

    Важно: Вставка всегда добавляет элемент как лист. 

🔹 Оценка эффективности

    Поиск позиции: Θ(h)
    Присоединение: O(1)
    Итог: Θ(h). Может деградировать до Θ(n) при неудачной последовательности вставок. Для гарантии Θ(log n) нужны сбалансированные деревья.

## Билет 22. Бинарные деревья поиска: удаление элемента. Оценки эффективности.

Алгоритм удаления (унифицированный через Node** cur)

    Найти реально удаляемый узел y:

        Если у x ≤ 1 ребёнка → y = x.

        Иначе y = последующий элемент для x 
    (минимум правого поддерева). 
    У y гарантированно ≤ 1 ребёнок.

    Найти поддерево p узла y и родителя par.

    Перенастроить связи:
        Если p != NULL → p->parent = par
        Если par == NULL → root = p (удалялся корень)
        Иначе → par->left/right = p

    Копирование данных: Если y ≠ x, скопировать key и info из y в x.
    Освободить память y. 

Оценка эффективности

    Поиск y и par: Θ(h)
    Перенастройка + копирование: O(1)
    Итог: Θ(h).

## Билет 23. Красно-черные деревья: определение, представление в памяти. Повороты. Оценка эффективности.

Определение красно-черного дерева и его свойства

Красно-черное (RB — Red-Black) дерево — это двоичное (бинарное) дерево поиска, у которого каждому узлу сопоставляется дополнительная информация — цвет (красный или черный).

Дерево называется красно-черным, если оно удовлетворяет следующим 5 свойствам:

    Каждый узел является либо красным (RED), либо черным (BLACK).

    Корень дерева является черным.

    Все внешние листья (ограничители) являются черными.

    Если узел красный, то оба его потомка черные (красные узлы не могут идти подряд).

    Все пути, ведущие от любого узла к его листьям-потомкам, содержат одинаковое количество черных узлов.

2. Представление в памяти и структура узла

В отличие от стандартного бинарного дерева поиска, узел КЧ-дерева обязательно содержит указатель на родительский узел (parent) для обеспечения возможности движения «вверх» при балансировке, а также поле цвета.

На языке C структура узла выглядит следующим образом:
C
```
typedef struct Node {
    int color;           // 0 - RED, 1 - BLACK
    int key;             // Ключ узла
    struct Node *left;   // Указатель на левого потомка
    struct Node *right;  // Указатель на правого потомка
    struct Node *parent; // Указатель на родительский узел
} Node;
```

Использование ограничителя (EList)


    Все концевые указатели left и right внутренних узлов ссылаются на один и тот же адрес объекта EList.

    Цвет EList всегда ЧЕРНЫЙ. Поля key и parent для него не используются.

    Это позволяет избавиться от постоянных проверок на NULL в алгоритмах.

3. Повороты (Rotations)

Повороты — это локальные операции над указателями дерева, которые изменяют его структуру (высоту поддеревьев), но строго сохраняют свойства бинарного дерева поиска (порядок следования ключей: слева — меньшие, справа — большие).

    Левый поворот (Left_Rotate(X)):
    Применяется к узлу X, у которого правый поток Y не является EList. Узел X опускается налево, становясь левым потомком Y. Левое поддерево узла Y (если оно было) становится правым поддеревом узла X. Указатели родителей перестраиваются.

    Правый поворот (Right_Rotate(Y)):
    Симметричная операция. Применяется к узлу Y, у которого левый потомок X не является EList. Узел Y опускается направо, становясь правым потомком X. Правое поддерево узла X становится левым поддеревом узла Y.

4. Оценка эффективности

    Черная высота узла bh(x) — это количество черных узлов на пути от x (не включая сам узел x) до любого листа EList.

    Высота дерева (h): Высота КЧ-дерева с n внутренними узлами удовлетворяет строгому неравенству:
    ```
    h≤2⋅log2​(n+1)
    ```

    Сложность операций: Так как высота гарантированно логарифмическая, операции поиска (Search), нахождения минимума/максимума, а также вставки (Insert) и удаления (Delete) выполняются за время O(logn) в худшем случае. Время выполнения самих поворотов составляет O(1).

## Билет 24. Красно-черные деревья: общий алгоритм вставки нового элемента. Нарушение свойств красно-черного дерева при вставке.

Общий алгоритм вставки (Insert)

Алгоритм добавления нового ключа в КЧ-дерево состоит из:

    Поиск места для вставки: Дерево обходится сверху вниз от корня, как в обычном дереве поиска, пока не будет найден лист EList, на место которого должен встать новый элемент.

    Создание и инициализация узла:

        Вставляется новый динамический узел x с заданным ключом.

        Указатели left и right нового узла инициализируются ссылками на EList.

        Важное правило: узел x всегда изначально окрашивается в КРАСНЫЙ цвет (x->color = RED).

    Восстановление свойств КЧ-дерева: Вызывается корректирующая процедура RB_Insert_Fixup(x).

2. Нарушение свойств красно-черного дерева при вставке

Поскольку новый узел x всегда окрашивается в красный цвет, то:

    Свойство 5 (Равенство черной высоты) — гарантированно НЕ нарушается, так как новый узел добавляет 0 к числу черных узлов на путях.

    Свойства 1 и 3 — также не нарушаются (EList остается черным, цвета только RED/BLACK).

Какие свойства МОГУТ нарушиться:

    Свойство 2 (Корень черный): Если дерево было абсолютно пустым (состояло только из EList), то новый узел x станет корнем дерева. Поскольку он красный, свойство 2 нарушится. (Исправляется тривиально: в конце алгоритма корень принудительно перекрашивается в черный цвет).

    Свойство 4 (Красный узел имеет черных потомков): Это основное и критическое нарушение. Оно возникает в случае, если родитель нового узла (p1) тоже является КРАСНЫМ. В дереве появляются два красных узла подряд (родитель и сын), что недопустимо. Именно это нарушение устраняет процедура балансировки.
