## Билет 1 Методологии программирования. Понятие алгоритма. Способы записи алгоритмов.

Методологии
	
1. Хаотическое – написание кода без предварительного проектирования.

2. Структурное – использование последовательности, ветвлений, циклов; отказ от goto.

3. Объектно-ориентированное (ООП) – инкапсуляция, наследование, полиморфизм, абстракция (кто питон учил, те запомнили уже)

Понятие алгоритма
	
• Формула Вирта: Программа = Алгоритм + Данные

• Определение: корректно определённая вычислительная процедура, на вход которой подаётся величина (или набор), а результатом является выходная величина (или набор).

• Схема: Входные данные → [Алгоритм] → Выходные данные

• Пример: задача сортировки {a₁...aₙ} → {a₁'≤a₂'≤...≤aₙ'}

Эффективность
	
t = k / v, где k – количество операций, v – быстродействие процессора.

Сравнение:
• Вставками: k₁ = c₁·n², c₁=2, v₁=10⁹ → при n=10⁹ ≈ 2000 сек
• Слиянием: k₂ = c₂·n·log₂n, c₂=50, v₂=10⁷ → при n=10 ≈ 2,3 дня

Способы записи
	
1. Словесное описание
2. Схема алгоритма (блок-схема)
3. Псевдокод
4. Программа на ЯП

## Билет 6. Элементарные структуры данных: стек и очередь, представленные списком.

 Очередь (FIFO) - first int first out

    Динамическая структура с двумя концами (голова head, хвост tail).

    Реализация на векторе (циклический буфер):
        Пуста: head == tail (или n == 0)
        Запись: queue[tail] = info; tail = (tail + 1) % N
        Полна: head == tail (или n == N)
        Чтение: info = queue[head]; head = (head + 1) % N

    Использование % N позволяет эффективно переиспользовать освободившиеся ячейки без сдвигов.
    N- размер очереди

Стек на списке

    Вставка/извлечение всегда с головы (top).
    Push: x->next = top; top = x;
    Pop: x = top; top = top->next; x->next = NULL;
    Сложность: O(1), без необходимости сдвига памяти.

Очередь на линейном списке

    Вставка в хвост (tail), извлечение из головы (head).
    Пустая: head = NULL, tail = NULL

Очередь на циклическом списке

    Используется один указатель tail. Начало очереди: head = tail->next.

Преимущество: постоянный доступ к обоим концам за O(1), экономия памяти (один указатель вместо двух)

## Билет 7. Таблицы: основные определения, классификация таблиц, способы отображения в памяти.

1. Определение

Таблица — это динамическое множество элементов, каждый из которых состоит из пары (Ключ, Информация).

    Ключ key — уникальное значение, идентифицирующее элемент.

    Информация  info — сопутствующие данные.

2. Основные операции

    Поиск (Search): найти элемент по ключу.

    Вставка (Insert): добавить новый элемент (если ключа нет).

    Удаление (Delete): убрать элемент по ключу.

3. Классификация таблиц


    Просматриваемые (неупорядоченные): элементы хранятся в порядке поступления, поиск только линейный.

    Упорядоченные: элементы отсортированы по ключу, возможен бинарный поиск.

    С вычисляемым входом (Хеш-таблицы): 
    
    адрес вычисляется функцией h(k).

        Прямая адресация: r(k) уникальна для каждого ключа.

        Перемешанные (Hash): возможны коллизии.

    Произвольного доступа: прямой доступ по индексу (массив).

4. Отображение в памяти (Слайды 3.4–3.7)

    Вектор (массив): непрерывная область памяти. Доступ по индексу O(1)

    Список: элементы связаны указателями. Доступ последовательный.

    Сеть: произвольные связи (граф).

## Билет 8. Просматриваемая таблица – вектор: определение, основные операции, особенности их реализации.

Суть: Элементы не сортируются. Хранятся в массиве.
Операции и реализации 

    Поиск (Search):
        Линейный просмотр от 0 до n−1
        Сложность: Θ(n).
    Вставка (Insert):
        Сначала Search (чтобы не было дубликатов).
        Если места нет → отказ.
        Иначе запись в конец: table[n] = new_elem, n = n + 1.
        Сложность: Θ(n) (доминирует поиск).
    Удаление (Delete):
        Найти элемент (индекс i).
        Заменить его последним элементом таблицы: table[i] = table[n-1].

        Уменьшить размер: n = n - 1.

        Важно: Порядок элементов нарушается, но это допустимо для просматриваемой таблицы.

        Сложность: Θ(n)

## Билет 10. Упорядоченная таблица: определение, основные операции, особенности их реализации.

Суть: Ключи всегда отсортированы (k1<k2<⋯<kn)

Операции

        Сложность: Θ(n).

    Минус: Если множество ключей U велико, а активных элементов n мало, память расходуется неэффективно (много пустых ячеек).

Суть: Таблица — это массив указателей на головы связных списков (цепочек).

Открытая таблица с закрытой адресацией

Операции

    Вставка:
        Вычислить idx=h(k)
        Проверить, нет ли ключа в списке table[idx].
        Добавить элемент в начало списка table[idx].
    Поиск:
        Вычислить idx=h(k)
        idx=h(k).
        Линейный поиск в списке table[idx].
    Удаление:
        Найти элемент в списке table[idx] и удалить узел.

Оценка эффективности 

    Коэффициент заполнения: σ=n/m (средняя длина цепочки).
    Средний случай: Θ(1+σ)
    Худший случай: Θ(n) (все ключи попали в одну цепочку).

## Билет 14: Хеш-таблицы с открытой адресацией
Суть: Все элементы хранятся непосредственно в ячейках массива таблицы. Списков нет.

Основные понятия 

    Последовательность исследований: h(k,0),h(k,1),
    h(k,0),h(k,1),— это перестановка индексов 0..m−1

    Статусы ячеек или поле busy
        FREE (0) — ячейка никогда не использовалась.
        OCCUPIED (1) — ячейка занята.
        DELETED (2) — ячейка была занята, но элемент удален.

Особенности 

    Поиск: останавливается при встрече FREE. DELETED пропускает.

    Вставка: может использовать ячейки со статусом DELETED или FREE. Лучще запоминать обе, потому что при поиске мы обязаны дойти до конца и их сравнивать, чтобы вставить в ближайшую (Овчаренко подшар)

    Удаление: нельзя ставить статус FREE (это разорвет цепочку пробирования для других элементов). Ставится статус DELETED.

## Билет 16: Хеш-таблица: квадратичное исследование, двойное хеширование. Оценка эффективности.

1. Квадратичное исследование (Quadratic Probing)

Это метод разрешения коллизий в открытой адресации, при котором расстояние между следующими проверяемыми ячейками растет квадратично.
Хеш-функция:
```
h(k,i)=(h′(k)+c1⋅i+c2⋅i^2)(mod m)

    k — ключ.
    i — номер исследования (пробирования), i=0,1,2, ...

    h′(k) — вспомогательная хеш-функция (базовая позиция).

    m — размер таблицы.

    c1​,c2​ — вспомогательные константы c1,c2≠0
```

Особенности:

    Позволяет избежать первичной кластеризации (когда блоки занятых ячеек сливаются в длинные цепочки, как при линейном пробировании).
    Ограничения: Для того чтобы последовательность проб была перестановкой 0,…,m−1  (т.е. чтобы алгоритм гарантированно нашел свободное место, если оно есть), требуется выбор специальных значений c1,c2 и m
    m выбирают простым числом, а константы так, чтобы покрыть хотя бы половину таблицы.

2. Двойное хеширование (Double Hashing)

Один из лучших методов открытой адресации. Использует две хеш-функции.
Хеш-функция:
```
h(k,i)=(h1(k)+i⋅h2(k))(modm)

    h1​(k) — основная хеш-функция (определяет начальную позицию).
    h2​(k) — вторая хеш-функция (определяет шаг смещения).
    i — номер попытки.
```

Ключевые требования:

    Значение h2(k)
    h2​(k) должно быть взаимно простым с размером таблицы m.
        Вариант реализации: 
        m — простое число, а h2(k)
        h2​(k) возвращает натуральные числа, меньшие m (например, 1≤h2(k)<m1).
    Это гарантирует, что последовательность исследования будет перестановкой всех индексов таблицы 0,…,m−11

Преимущество:

    Минимизирует как первичную, так и вторичную кластеризацию. Элементы с разными ключами будут "прыгать" по таблице с совершенно разными шагами.

3. Оценка эффективности

Эффективность хеш-таблиц с открытой адресацией зависит от коэффициента заполнения:
```
σ=n/m
```
где
n — количество элементов,
m — размер массива.
Предполагается равномерное хеширование (все элементы отображаются на ячейки независимо и равновероятно).

## Билет 18 Деревья: определение, разновидности деревьев. Представление произвольного дерева с помощью двоичного дерева. Операции обхода дерева.

Определение и разновидности

    Дерево – множество вершин, которое либо пусто, либо состоит из корня и совокупности связанных с ним поддеревьев. Каждое поддерево само является деревом. 
    Разновидности:

        N-арное (произвольное): узел хранит массив указателей Node* ptrs[N] или динамический массив Node** ptrs. 

        Двоичное: корень + левое поддерево + правое поддерево. 

Представление произвольного дерева двоичным.

Используется схема «Левый ребёнок – Правый брат» :

    Поле left узла указывает на его самого левого дочернего узла.
    Поле right узла указывает на следующего брата (соседний дочерний узел того же родителя).
    Позволяет хранить дерево любой степени в памяти, используя стандартную структуру бинарного дерева.

## Билет 19. Бинарные деревья поиска: определение, обход дерева, операции поиска. Поиск по ключу, минимума и максимума. Оценки эффективности.

BST – дерево, где для любой вершины x с ключом k_x:

    Все ключи в левом поддеревье Л[x] ≤ k_x
    Все ключи в правом поддеревье П[x] ≥ k_x
    Каждая вершина помечена отдельным ключом. 

Обход и поиск

    Центрированный обход BST выдаёт ключи в строго возрастающем порядке. 

    Поиск по ключу: сравниваем с текущим узлом. Если < → влево, если > → вправо, если == → успех. Дошли до NULL → отказ. 

    Поиск минимума: двигаться по указателям left до NULL. 

    Поиск максимума: двигаться по указателям right до NULL. 

Оценка эффективности

Все операции поиска выполняются за Θ(h), где h – высота дерева.

    Худший случай: дерево вырождено в список → h = n → Θ(n).

    Средний/оптимальный случай: сбалансировано → h ≈ log₂n → Θ(log n). 

## Билет 20. Бинарные деревья поиска: поиск предшествующего и последующего элементов. Оценки эффективности.

Определения

    Предшествующий (predecessor): элемент с наибольшим ключом < данного.

    Последующий (successor): элемент с наименьшим ключом > данного.

    Соответствуют соседям в последовательности центрированного обхода. 

Алгоритм поиска последующего (требует поле parent)

    Если есть правое поддерево: последующий = минимум правого поддерева (спуск влево до конца).

    Если правого поддерева нет: поднимаемся вверх по родителям, пока текущий узел не станет левым ребёнком своего родителя. Родитель этого узла и будет последующим.

    Если дошли до корня и не нашли → последующего нет (NULL). 

(Поиск предшествующего симметричен: если есть левое → максимум левого, иначе подъём вверх, пока узел не станет правым ребёнком.)

Оценка эффективности

В худшем случае Θ(n), в сбалансированном Θ(log n).

## Билет 21. Бинарные деревья поиска: вставка нового элемента. Оценки эффективности.

Алгоритм вставки

    Если дерево пусто (root == NULL) → новый элемент становится корнем.

    Иначе ищем позицию вставки, двигаясь от корня (как при поиске):

        Запоминаем текущего (cur) и его родителя (par).
        Если key_new < cur->key, тогда cur = cur->left, иначе cur = cur->right.

    Когда cur == NULL, присоединяем новый узел к par как левое или правое поддерево.

    Важно: Вставка всегда добавляет элемент как лист. 

 Оценка эффективности

    Поиск позиции: Θ(h)
    Присоединение: O(1)
    Итог: Θ(h). Может деградировать до Θ(n) при неудачной последовательности вставок. Для гарантии Θ(log n) нужны сбалансированные деревья.

## Билет 22. Бинарные деревья поиска: удаление элемента. Оценки эффективности.

Алгоритм удаления (унифицированный через Node** cur)

    Найти реально удаляемый узел y:

        Если у x ≤ 1 ребёнка → y = x.

        Иначе y = последующий элемент для x 
    (минимум правого поддерева). 
    У y гарантированно ≤ 1 ребёнок.

    Найти поддерево p узла y и родителя par.

    Перенастроить связи:
        Если p != NULL → p->parent = par
        Если par == NULL → root = p (удалялся корень)
        Иначе → par->left/right = p

    Копирование данных: Если y ≠ x, скопировать key и info из y в x.
    Освободить память y. 

Оценка эффективности

    Поиск y и par: Θ(h)
    Перенастройка + копирование: O(1)
    Итог: Θ(h).

## Билет 23. Красно-черные деревья: определение, представление в памяти. Повороты. Оценка эффективности.

Определение красно-черного дерева и его свойства

Красно-черное (RB — Red-Black) дерево — это двоичное (бинарное) дерево поиска, у которого каждому узлу сопоставляется дополнительная информация — цвет (красный или черный).

Дерево называется красно-черным, если оно удовлетворяет следующим 5 свойствам:

    Каждый узел является либо красным (RED), либо черным (BLACK).

    Корень дерева является черным.

    Все внешние листья (ограничители) являются черными.

    Если узел красный, то оба его потомка черные (красные узлы не могут идти подряд).

    Все пути, ведущие от любого узла к его листьям-потомкам, содержат одинаковое количество черных узлов.

2. Представление в памяти и структура узла

В отличие от стандартного бинарного дерева поиска, узел КЧ-дерева обязательно содержит указатель на родительский узел (parent) для обеспечения возможности движения «вверх» при балансировке, а также поле цвета.

На языке C структура узла выглядит следующим образом:
C
```
typedef struct Node {
    int color;           // 0 - RED, 1 - BLACK
    int key;             // Ключ узла
    struct Node *left;   // Указатель на левого потомка
    struct Node *right;  // Указатель на правого потомка
    struct Node *parent; // Указатель на родительский узел
} Node;
```

Использование ограничителя (EList)


    Все концевые указатели left и right внутренних узлов ссылаются на один и тот же адрес объекта EList.

    Цвет EList всегда ЧЕРНЫЙ. Поля key и parent для него не используются.

    Это позволяет избавиться от постоянных проверок на NULL в алгоритмах.

3. Повороты (Rotations)

Повороты — это локальные операции над указателями дерева, которые изменяют его структуру (высоту поддеревьев), но строго сохраняют свойства бинарного дерева поиска (порядок следования ключей: слева — меньшие, справа — большие).

    Левый поворот (Left_Rotate(X)):
    Применяется к узлу X, у которого правый поток Y не является EList. Узел X опускается налево, становясь левым потомком Y. Левое поддерево узла Y (если оно было) становится правым поддеревом узла X. Указатели родителей перестраиваются.

    Правый поворот (Right_Rotate(Y)):
    Симметричная операция. Применяется к узлу Y, у которого левый потомок X не является EList. Узел Y опускается направо, становясь правым потомком X. Правое поддерево узла X становится левым поддеревом узла Y.

4. Оценка эффективности

    Черная высота узла bh(x) — это количество черных узлов на пути от x (не включая сам узел x) до любого листа EList.

    Высота дерева (h): Высота КЧ-дерева с n внутренними узлами удовлетворяет строгому неравенству:
    ```
    h≤2⋅log2​(n+1)
    ```

    Сложность операций: Так как высота гарантированно логарифмическая, операции поиска (Search), нахождения минимума/максимума, а также вставки (Insert) и удаления (Delete) выполняются за время O(logn) в худшем случае. Время выполнения самих поворотов составляет O(1).

## Билет 24. Красно-черные деревья: общий алгоритм вставки нового элемента. Нарушение свойств красно-черного дерева при вставке.

Общий алгоритм вставки (Insert)

Алгоритм добавления нового ключа в КЧ-дерево состоит из:

    Поиск места для вставки: Дерево обходится сверху вниз от корня, как в обычном дереве поиска, пока не будет найден лист EList, на место которого должен встать новый элемент.

    Создание и инициализация узла:

        Вставляется новый динамический узел x с заданным ключом.

        Указатели left и right нового узла инициализируются ссылками на EList.

        Важное правило: узел x всегда изначально окрашивается в КРАСНЫЙ цвет (x->color = RED).

    Восстановление свойств КЧ-дерева: Вызывается корректирующая процедура RB_Insert_Fixup(x).

2. Нарушение свойств красно-черного дерева при вставке

Поскольку новый узел x всегда окрашивается в красный цвет, то:

    Свойство 5 (Равенство черной высоты) — гарантированно НЕ нарушается, так как новый узел добавляет 0 к числу черных узлов на путях.

    Свойства 1 и 3 — также не нарушаются (EList остается черным, цвета только RED/BLACK).

Какие свойства МОГУТ нарушиться:

    Свойство 2 (Корень черный): Если дерево было абсолютно пустым (состояло только из EList), то новый узел x станет корнем дерева. Поскольку он красный, свойство 2 нарушится. (Исправляется тривиально: в конце алгоритма корень принудительно перекрашивается в черный цвет).

    Свойство 4 (Красный узел имеет черных потомков): Это основное и критическое нарушение. Оно возникает в случае, если родитель нового узла (p1) тоже является КРАСНЫМ. В дереве появляются два красных узла подряд (родитель и сын), что недопустимо. Именно это нарушение устраняет процедура балансировки.

## Билет 26. Красно-черное дерево: общий алгоритм удаления элемента. Нарушение свойств красно-черного дерева при удалении.

Общий алгоритм удаления (RB_Delete)

Удаление узла основано на стандартной процедуре бинарного дерева поиска:

    Находится узел z, который требуется удалить.

    Определяется узел y, который будет фактически извлечен из памяти:

        Если у z менее двух внутренних детей (ноль или один), то удаляется сам z (y=z).

        Если у z два внутренних ребенка, то ищется узел y, следующий за ним по порядку (самый левый узел в правом поддереве z). Значение ключа из y копируется в узел z, а сам узел y подлежит физическому удалению.

    Таким образом, узел y гарантированно имеет не более одного внутреннего потомка. Обозначим этого единственного потомка (или EList, если детей нет) как x.

    Узел y вырезается из дерева, а узел x встает на его место (его родитель теперь указывает на родителя y).

    Анализ цвета удаленного узла y:

        Если y был КРАСНЫМ, балансировка не требуется (удаление красного узла не меняет черную высоту путей и не может создать две красные вершины подряд).

        Если y был ЧЕРНЫМ, свойства дерева нарушаются, и вызывается процедура RB_Delete_Fixup(x).

2. Нарушение свойств красно-черного дерева при удалении

Когда из дерева удаляется черный узел y, на всех путях, проходивших через этот узел, исчезает один черный узел.

Возникающие нарушения:

    Нарушение свойства 5 (Черная высота): Пути, проходящие через место удаленного узла, теперь содержат на одну черную вершину меньше, чем все остальные пути в дереве.

    Нарушение свойства 4: Если родитель узла y был красным, а вставший на его место узел x тоже красный, возникает недопустимая пара красных узлов подряд.

    Нарушение свойства 2: Если удаленный черный узел был корнем дерева, а на его место встал красный узел x.

Концепция решения: Чтобы сбалансировать черную высоту, узел x (занявший место удаленного черного узла) условно наделяется «дополнительным черным цветом».

    Если x изначально был красным, он становится черно-красным. Мы можем просто покрасить его в обычный ЧЕРНЫЙ цвет, добавив недостающую единицу черной высоты, и на этом закончить.

    Если x изначально черный, он становится «двукратно черным» (DOUBLE BLACK). Цель балансировки — «протолкнуть» эту лишнюю черноту вверх по дереву до корня или растворить ее с помощью перекрасок и поворотов.

## Билет 28. AVL-дерево: определение, способы задания узлов AVL-дерева. Общий алгоритм вставки в AVL-дерево. Коррекция узлов.

1. Определение

AVL-дерево (Г.М. Адельсон-Вельский, Е.М. Ландис, 1962) – это сбалансированное бинарное дерево поиска, в котором для любого узла высоты левого и правого поддеревьев отличаются не более чем на 1. 

Высота дерева h ограничена: log₂(n+1) ≤ h ≤ 1,404·log₂(n+2) – 0,328.

2. Способы задания узлов

Предложены три варианта структуры узла:

    С полем балансировки (balance):
    balance = -1 → левое поддерево выше на 1; 0 → высоты равны; +1 → правое выше на 1.
    ```
    struct Node { int balance; int key; Node *left, *right, *parent; };
    ```
    С полями высот поддеревьев:
    ```
    struct Node { int hleft, hright; int key; Node *left, *right, *parent; };
    ```
    Хранит фактические высоты левого и правого поддеревьев.

    С полем высоты:
    ```
    struct Node { int height; int key; Node *left, *right, *parent; };
    ```
    Но его придётся каждый раз пересчитывать, не очень удобно

3. Общий алгоритм вставки

    Вставить новый ключ как в обычное бинарное дерево поиска (рекурсивно или итеративно до листа).

    После физической вставки начать подъём от нового узла к корню.

    На каждом шаге обновлять баланс/высоту родительского узла.

4. Коррекция узлов (проход вверх)

    Пока родитель p существует и p->balance == 0:

        Если вставка была в левое поддерево p → p->balance = -1, иначе +1.
        Перейти к следующему предку.

    Если встретился узел с p->balance ≠ 0:

        Если вставка компенсировала наклон (например, вставка в левое поддерево при balance == +1) → p->balance = 0, коррекция завершена.

        Если наклон усилился (balance стал +2 или -2) → требуется коррекция дерева (повороты, билет 29).

## Билет 30. Удаление элемента из AVL-дерева: общий алгоритм. Коррекция узлов AVL-дерева.

1. Общий алгоритм удаления

    Удаляется элемент так же, как в обычном бинарном дереве поиска.

    Если удаляемый узел имеет два ребёнка, он заменяется наименьшим ключом правого поддерева (или наибольшим левого), после чего фактическое удаление происходит в листе (или узле с одним ребёнком).

    Внешние листья обозначаются как EList (пустые указатели).

2. Коррекция узлов после удаления

    x – ребёнок удалённого узла (или лист, из которого удалили).

    Поднимаемся вверх по родителям p = x->parent.

    На каждом шаге уменьшаем высоту соответствующего поддерева p (p->hleft-- или p->hright--).

    Вычисляем dh = |p->hleft – p->hright|:

        dh > 1 → нарушение баланса, требуется коррекция дерева (билет 31). После неё алгоритм завершается (успех).
        dh == 1 → баланс восстановлен, но высота поддерева уменьшилась на 1. В данной реализации считается успех (коррекция локально завершена).
        dh == 0 → высота поддерева не изменилась, но баланс изменился. Продолжаем подъём: x = p; p = x->parent

## Билет 32. B дерево: определение, структура узла. Поиск в B-дереве.

1. Определение

B-дерево степени t (t ≥ 2) – многопоисковое сбалансированное дерево, оптимизированное для внешней памяти.

    Каждый внутренний узел (кроме корня) имеет от t до 2t дочерних узлов.
    Содержит от t–1 до 2t–1 ключей. Узел полон, если ключей 2t–1.
    Корень имеет минимум 1 ключ и 2 потомка (если не является листом).
    Все листья находятся на одной глубине h.
    Ключи в узле упорядочены: k₁ ≤ k₂ ≤ … ≤ kₙ₋₁.

Варианты:
- 1970 г. Джон Хопкрофт (John E. Hopcroft)
– 2-3 деревья: каждый внутренний узел имеет
2 или 3 дочерних узла, все листья – на одном
уровне
- 2-3-4 деревья: каждый внутренний узел имеет
2, 3 или 4 дочерних узла
- 1972 г. Р. Байер (R. Bayer) и Э. Мак-Крэйт (E.M.
McCreight) – B деревья
2. Структура узла (C-подобная)
```
const int T = ...; // степень дерева
struct Node {
    int n;                // текущее количество ключей
    int key[2*T - 1];     // массив ключей
    Node* ptr[2*T];       // указатели на дочерние узлы (у листьев = NULL)
    Node* parent;         // указатель на родителя
};
```
3. Поиск

    Начинаем с корня x.

    В текущем узле ищем позицию i, такую что key[i-1] < k ≤ key[i].

    Если k == key[i] → успех (возвращаем указатель на узел и позицию).

    Если k < key[0] → спускаемся по ptr[0].

    Если k > key[n-1] → спускаемся по ptr[n].

    Иначе → спускаемся по ptr[i].

    Повторяем, пока не найдём ключ или не достигнем NULL (лист без ключа) → отказ.

    Сложность: O(log_t n) обращений к узлам.

## Билет 33. Вставка нового элемента в B-дерево.

1. Общий принцип

    Новый элемент всегда вставляется в лист.

    Если лист заполнен (2t-1 ключей), происходит разбиение (split):

        Медианный ключ перемещается в родительский узел.
        Лист делится на два узла по t-1 ключей.
    Если родитель тоже заполнен, разбиение рекурсивно поднимается вверх.

    Если переполняется корень, создаётся новый корень, высота дерева увеличивается на 1.

2. Алгоритм B_Tree_Insert(root, k)

    Если корень полон: создать новый узел s, сделать его корнем, старый корень прикрепить как s->ptr[0], вызвать B_Tree_Split(s, 0).

    Вызвать B_Insert_Nonfull(r, k):

        Пока x не лист:
            Найти позицию i для k.
            Если x->ptr[i] полон → B_Tree_Split(x, i).
            Выбрать нужный указатель (ptr[i] или ptr[i+1] в зависимости от k) и спуститься.

        Вставить k в лист x, сохраняя порядок ключей.

3. Разбиение узла B_Tree_Split(x, i)

    y = x->ptr[i] (полный узел, 2t-1 ключей).

    Сдвинуть в x ключи и указатели, начиная с i, вправо.

    Создать новый узел z.

    Переместить в z ключи и указатели из y, начиная с j = t.

    Медианный ключ y->key[t-1] поместить в x->key[i].

    Указать x->ptr[i+1] = z.

    Скорректировать счётчики ключей в x, y, z.

## Билет 34. Удаление элемента из B-дерева.

1. Общий алгоритм

    Если ключ в листе → просто удалить.

    Если ключ во внутреннем узле → заменить его ближайшим значением из поддерева (наименьшим ключом правого потомка или наибольшим левого), затем удалить этот ключ из листа.

    После удаления проверить лист на антипереполнение (< t-1 ключей). Если нарушено → коррекция.

2. Способы коррекции при антипереполнении

    Перераспределение (заимствование):
    Если соседний узел (левый или правый) имеет ≥ t ключей, берём у него один ключ через родительский разделитель. 
     Разделитель опускается в deficient-узел, ключ соседа поднимается в родитель. Указатели корректируются.

    Слияние:
        Если оба соседа имеют только t-1 ключей, объединяем deficient-узел с соседом и родительским разделителем в один узел (2t-1 ключей). Родитель теряет ключ и указатель. Если родитель сам оказался в антипереполнении, процесс повторяется вверх.

3. Обработка корня и особые ситуации

    Ситуация 1 (ключ не в текущем узле): Спускаемся в поддерево, которое должно содержать ключ. Если этот узел имеет t-1 ключей, пытаемся заимствовать у соседа или сливаем с соседом и разделителем родителя.

    Ситуация 2 (ключ в текущем узле): Заменяем на предшественника/преемника, спускаемся в соответствующее поддерево, применяем те же правила заимствования/слияния.

    Слияние корня: Если корень содержит 1 ключ, а оба его потомка имеют по t-1 ключу, все три узла сливаются в один. Новый узел становится корнем, высота дерева уменьшается на 1.

## Билет 39. Графы: определение, ориентированный и неориентированный графы, взвешенные графы. Понятие пути в графе, длина пути. Представление графа.

1. Определение

Граф G = (V, E):
    V — множество вершин (нод)
    E — множество рёбер (пар вершин)

2. Виды графов

Неориентированный

	Рёбра не имеют направления: (u,v) ≡ (v,u)
	

Ориентированный
	
    Рёбра — дуги: (u→v) ≠ (v→u)
	

Взвешенный
	
    Каждому ребру сопоставлен вес w(u,v)
	
Связный
	
    Между любыми двумя вершинами есть путь
	
Полный
	
    Каждая пара вершин соединена ребром
	
3. Основные понятия

    Путь — последовательность вершин v₁, v₂, ..., vₖ, где (vᵢ, vᵢ₊₁) ∈ E

    Длина пути — количество рёбер (или сумма весов во взвешенном графе)

    Цикл — путь, где v₁ = vₖ

    Степень вершины — количество инцидентных рёбер (для орграфа: полустепень захода/исхода)

4. Представление графа в памяти

Матрица смежности

    Плюсы: проверка ребра O(1), удобно для плотных графов
    Минусы: память O(V²), перебор соседей O(V)


Списки смежности

    Плюсы: память O(V+E), перебор соседей O(deg(v))
    Минусы: проверка ребра O(deg(v))


Список рёбер

    Подходит для алгоритмов Крускала, Форда-Беллмана


## Билет 40. Алгоритмы обхода графа: поиск в ширину, поиск в глубину.

        u = dequeue(Q)
        Для каждого соседа v ∈ Adj[u]:
            Если color[v] == белый: color[v]=серый, d[v]=d[u]+1, pred[v]=u, enqueue(Q)
        color[u]=черный

Сложность: O(V + E) (каждая вершина и ребро обрабатываются один раз)

2. Поиск в глубину (DFS — Depth-First Search)

Идея: идти «вглубь» по одному пути до тупика, затем возвращаться (backtracking). Использует стек (явно или рекурсию).

Применение: топологическая сортировка, поиск компонент связности, обнаружение циклов.

Алгоритм:

    Инициализация: color[v]=белый, pred[v]=NULL, time=0.
    Для каждой вершины u ∈ V: если color[u]==белый → DFS_Visit(u).
    DFS_Visit(u):
        color[u]=серый, time++, d[u]=time (время открытия)
        Для каждого v ∈ Adj[u]: если color[v]==белый → pred[v]=u, DFS_Visit(v)
        color[u]=черный, time++, f[u]=time (время завершения)

Сложность: O(V + E)

## Билет 41. Поиск кратчайшего пути в графе. Алгоритм Дейкстры.

Задача: Найти кратчайшие пути от одного истока s до всех вершин в графе с неотрицательными весами рёбер.

Ключевая операция – Ослабление (Relax): - да и вообще зачилльтесь)
```
f (d[v] > d[u] + w(u,v)) {
    d[v] = d[u] + w(u,v);
    pred[v] = u;
}
```
Алгоритм:

    Инициализация: d[v]=∞, pred[v]=NULL для всех v. d[s]=0. S=∅ (множество обработанных вершин). 
    Q=V (очередь с приоритетами по d).

    Пока Q не пуста:
        u = Extract_Min(Q) (вершина с минимальной оценкой)
        S = S ∪ {u}
        Для каждого соседа v ∈ Adj[u]: выполнить Relax(u, v)

Сложность:

    Массив/вектор для Q: O(|V|²)
    Бинарная куча: O(|E| log |V|)
    Куча Фибоначчи: O(|V| log |V| + |E|)

Проблемка: Не работает с отрицательными весами рёбер.

## Билет 42. Топологическая сортировка.

Определение: Линейное упорядочение вершин ориентированного ациклического графа (DAG), такое что для любого ребра (u, v) вершина u стоит в списке раньше v.

Алгоритм (на основе DFS):

    Вызвать DFS(G) для вычисления времени завершения f[v] каждой вершины.

    При завершении вершины (окрашивание в чёрный) вставлять её в начало связного списка.

    Вернуть список. Версии расположены в порядке убывания f[v].

Сложность: O(|V| + |E|) (время DFS + O(1) на вставку в начало списка).


## Билет 43. Задача о кратчайшем пути. Алгоритм Беллмана-Форда.

Задача: Найти кратчайшие пути от истока s в графе с возможными отрицательными весами. Обнаруживает циклы отрицательного веса, достижимые из s.

Алгоритм:

    Инициализация: d[s]=0, d[v]=∞, pred[v]=NULL.

    Цикл i от 1 до |V|-1:
        Для каждого ребра (u, v) ∈ E: Relax(u, v)

    Проверка на цикл отрицательного веса:
        Для каждого (u, v) ∈ E: если d[v] > d[u] + w(u,v) → отказ (цикл есть).
        Иначе → успех, расстояния найдены.

Сложность: O(|V|·|E|).

Особенности: Медленнее Дейкстры, но универсальнее. Если после |V|-1 итераций можно ещё улучшить расстояние, значит существует цикл отрицательного веса.

## Билет 44. Алгоритм Флойда-Варшалла.

Задача: Найти кратчайшие пути между всеми парами вершин. Допускает отрицательные веса, но не циклы отрицательного веса.

Идея (Динамическое программирование):
d[i][j][k] – вес кратчайшего пути из i в j, использующего только промежуточные вершины из множества {1..k}.

```
d[i][j][k] = min( d[i][j][k-1],  d[i][k][k-1] + d[k][j][k-1] )
```

Итеративная реализация :
```
for (k = 1 to |V|)
  for (i = 1 to |V|)
    for (j = 1 to |V|)
      d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
```

Восстановление пути: матрица предшественников π[i][j], обновляется при сокращении пути.

Вообще можно всё построить по последней версии матрицы, бабка может это попросить сделать)

Сложность: Θ(|V|³) по времени, O(|V|²) по памяти.

## Билет 45. Поиск сильно связных компонентов.

Определение: Сильно связный компонент (SCC) – максимальное подмножество вершин C, где для любой пары u, v ∈ C существуют пути u → v и v → u.

Алгоритм (двойной DFS):

    Вызвать DFS(G), вычислить время завершения f[u] для каждой вершины.

    Построить транспонированный граф G^T (развернуть все рёбра).

    Вызвать DFS(G^T), но выбирать стартовые вершины в порядке убывания f[u] (от последней завершённой к первой).

    Каждое дерево, полученное на шаге 3, является одним сильно связным компонентом.

Сложность: O(|V| + |E|).

Идея: Вершина с максимальным f[u] принадлежит компоненту без исходящих рёбер в графе компонент. В G^T DFS «захватывает» весь компонент целиком.

## Билет 46. Минимальные остовные деревья. Построение минимального остовного дерева. Алгоритм Крускала.

Определение: Остовное дерево – ациклическое подмножество рёбер, соединяющее все вершины связного взвешенного графа. MST имеет минимальный суммарный вес.

Идея Крускала: Жадный алгоритм, работающий с лесом. 

Interesting fact:
Жадный (greedy) алгоритм - это алгоритм, который на каждом этапе принимает локально оптимальные решения, допуская, что итоговое решение окажется наиболее оптимальным. 
Алгоритм Дейкстры тоже является жадным, потому что при каждой итерации мы выбираем наименьший вес вершины, в надежде, что в итоге получим кратчайший путь. Вот такие пироги)
Но алгоритм Флойда-Варшалла не является жадным, хотя тоже ищет кратчайший маршрут, но только между всеми вершинами, этот алгоритм скорее относится к динамическому программированию. Ладно, отсутупление закончено)

Сортируем рёбра по весу. Последовательно добавляем легчайшее ребро, если оно соединяет два разных дерева (не создаёт цикл). Использует систему непересекающихся множеств (DSU).

Алгоритм:

    A = ∅. Для каждой v ∈ V: Make_Set(v).
    Отсортировать E по неубыванию веса.
    Для каждого (u, v) в отсортированном порядке:
        Если Find_Set(u) ≠ Find_Set(v):
            A = A ∪ {(u,v)}
            Union(u, v)
    Вернуть A.

Сложность: O(|E| log |E|) или O(|E| log |V|) из-за сортировки. DSU-операции почти O(1).

Теорема: Легкое ребро, пересекающее разрез, согласованный с A, безопасно для A.

## Билет 47. Минимальные остовные деревья. Построение минимального остовного дерева. Алгоритм Прима.

Идея Прима: Растим одно дерево из произвольного корня r. На каждом шаге добавляем вершину из V \ T, соединённую с T ребром минимального веса.

Структуры данных:

    key[v] – минимальный вес ребра, соединяющего v с текущим деревом (∞ изначально, key[r]=0).
    p[v] – родитель v в MST.
    Очередь с приоритетами Q хранит все вершины, приоритет = key[v].

Алгоритм:

    Инициализация: key[v]=∞, p[v]=NULL. key[r]=0. Q = V.
    Пока Q не пуста:
        u = Extract_Min(Q)
        Для каждого v ∈ Adj[u]:
            Если v ∈ Q и w(u,v) < key[v]:
                p[v] = u
                key[v] = w(u,v)

Сложность: Аналогична Дейкстре: O(|V|²) (массив) или O(|E| log |V|) (куча).

Отличие от Крускала: Прим растёт из одной вершины, Крускал объединяет множество деревьев.

## Билет 48. Транспортная задача. Транспортные сети и потоки.

Транспортная сеть: Ориентированный граф G=(V,E) с источником s (B(s)=∅) и стоком t (A(t)=∅). Каждому ребру (u,v) сопоставлена пропускная способность c(u,v) ≥ 0.

Поток f: V×V → R удовлетворяет трём свойствам:

    Ограничение пропускной способности: 0 ≤ f(u,v) ≤ c(u,v)

    Антисимметричность: f(u,v) = -f(v,u)

    Сохранение потока: ∀ u ∈ V \ {s,t}: Σ_{v∈V} f(v,u) = 0 (входящий = исходящий)

Величина потока: val(f) = Σ_{v∈V} f(s,v) (суммарный поток из источника).

Задача: Найти f, максимизирующий val(f) при заданных c.

## Билет 49. Транспортная задача. Базовый алгоритм Форда-Фалкерсона.

Ключевые понятия:

    Остаточная пропускная способность: c_f(u,v) = c(u,v) - f(u,v)
    Остаточная сеть G_f: Содержит рёбра с c_f(u,v) > 0.
    Увеличивающий путь: Простой путь из s в t в G_f. Его пропускная способность c_f(p) = min{c_f(u,v)} на пути.

Алгоритм:

    f(u,v) = 0 для всех рёбер.
    Пока существует увеличивающий путь p в G_f:
        c_f(p) = min остаточных пропускных способностей на p.
        Для каждого (u,v) ∈ p: f(u,v) += c_f(p), f(v,u) = -f(u,v)
    Вернуть f.

Теорема о максимальном потоке и минимальном разрезе:
val(f_max) = c(S,T)_min. Алгоритм завершается, когда в G_f нет увеличивающих путей.

Сложность: Зависит от поиска пути. При BFS  O(|V|·|E|²). Для целых пропускных способностей всегда завершается.

## Билет 50. Префиксные деревья Radix tree. Adaptive radix tree.

1. Основные свойства префиксных деревьев

Префиксное дерево (Trie) — структура данных для хранения множества строк, использующая их общие префиксы.

Свойства:

    Каждый внутренний узел помечен "разрядом ключа" (частичным ключом)
    Все дочерние узлы имеют различные значения разрядов
    Ключи не хранятся явно, а вычисляются при обходе
    Можно организовать обход с сохранением упорядоченности ключей

Пример ключей:

    Строки: каждый символ — разряд
    Целые числа: побайтовое разбиение
    Числа с плавающей точкой: с учётом структуры (знак, порядок, мантисса)

2. Radix Tree (сжатое префиксное дерево)

Определение:

Radix tree — модификация Trie, которая сжимает пути, храня в узлах не по одному разряду, а последовательности разрядов.

Преимущества:

    Уменьшает высоту дерева
    Экономит память при разреженном заполнении
    Сохраняет все свойства Trie

Ленивое расширение:

    Внутренний узел создаётся только если необходим для различения хотя бы двух дочерних узлов
    При вставке: поиск первого отличающегося разряда
    При удалении: сжатие пути (объединение узла с родителем, если один потомок)

3. Adaptive Radix Tree (ART)

Основная идея:

ART адаптирует размер узла в зависимости от количества дочерних элементов для оптимального использования памяти.

Типы внутренних узлов:

Node4
	
    до 4 элементов
	Массив из 4 ключей + 4 указателя

Node16
	
    5–16 элементов
	Упорядоченный массив ключей + указатели (бинарный поиск/SIMD)

Node48
	
    17–48 элементов
    Массив 256 индексов (6-бит) + массив 48 указателей


Node256
	
    до 256 элементов
	Массив из 256 указателей (как в классическом Trie)

Хранение сжатого пути:

Пессимистичный подход:

    В каждом узле хранится вектор частичных ключей
    При поиске сравнивается с искомым ключом
    Недостаток: больше памяти, фрагментация

Оптимистичный подход:

    Хранится только число удалённых предшествующих узлов
    При поиске пропускается соответствующее число разрядов
    В конце — проверка ключа в листе
    Преимущество: экономия памяти для длинных ключей

Листовые узлы:

    Отдельный тип узла с одним значением (просто, но увеличивает высоту)
    Несколько значений в соответствии с типом узла (не увеличивает высоту)
    Тегирование указателей: значение хранится вместо указателя, если помещается (самый эффективный)

Алгоритм вставки:

    Рекурсивный спуск до места вставки
    Если произошло ленивое расширение — замена листа внутренним узлом
    Если ключ отличается от сжатого пути — создание нового внутреннего узла
    Корректировка сжатых путей

Характеристики ART:

    Время поиска/вставки/удаления: O(k), где k — длина ключа
    Память: адаптивная, значительно экономнее классического Trie
    Кэш-дружественность: высокая благодаря компактным узлам
    SIMD-оптимизации: для Node16

4. Области применения префиксных деревьев

    Поиск подстрок (Ахо-Корасик)
    Сжатие данных
    Анализ естественных языков
    Хранение словарей
    Индексы баз данных
    Представление индексированных данных в ядре Linux  

## Билет 51. Персистентные структуры данных. Персистентность структур данных. Виды персистентности.

1. Основные понятия

Эфемерная структура данных

    Хранит только одно последнее состояние (любая классическая структура данных: стек, очередь, дерево и т.д.)
    Любое изменение безвозвратно перезаписывает предыдущее состояние

Персистентная структура данных

    «Помнит» все свои предыдущие состояния (версии)
    Позволяет осуществлять доступ и операции над любой из сохранённых версий
    Любое изменение порождает новую версию, не затрагивая старые

2. Виды персистентности

Частичная (Partial)
	
    Чтение любой версии, но изменение — только последней
    Линейный список (цепочка)
	Read(Vᵢ), Write(Vₙ)

Полная (Full)

	Чтение и изменение любой версии; изменения не влияют на другие версии
	Дерево версий
	Read(Vᵢ), Write(Vᵢ)

Конфлюентная (Confluent)

	Операции могут объединять несколько версий; изменения в одной версии могут влиять на другие
	Ориентированный ациклический граф (DAG)
	Read(Vᵢ), Write(Vᵢ), Merge(Vᵢ, Vⱼ)

Функциональная (Functional)

	Персистентность в парадигме функционального программирования: данные неизменяемы после создания
	Любая из вышеперечисленных
	Только создание новых версий

3. Области применения персистентных структур

        Системы контроля версий (Git, SVN)
        Файловые системы с снапшотами (ZFS, Btrfs)
        Текстовые/графические редакторы (отмена/повтор действий)
        Функциональное программирование (Haskell, Clojure)
        Распределённые вычисления и репликация данных
        Базы данных с поддержкой временных запросов (temporal DB)
        Машинное обучение (откат к предыдущим состояниям модели)
        Криптография и блокчейн (история изменений)
        Геометрические алгоритмы (плоскость, пространство)

4. Способы достижения персистентности

    4.1. Полное копирование (Naive Copy)

    При каждом изменении создаётся полная копия всей структуры
    Плюсы: простота реализации
    Минусы: 
        Временная сложность: O(n) на операцию
        Пространственная сложность: O(n·V), где V — число версий
    Применение: только для очень маленьких объектов или прототипирования

    4.2. Копирование пути (Path Copying)

    Подходит для структур в Pointer-machine модели (узлы с указателями)

Алгоритм:

    При изменении узла — копируем только этот узел
    Вносим изменения в копию
    Копируем все узлы, которые указывают на изменённый, обновляя в них указатели
    Повторяем рекурсивно до корневого узла
    Новая версия начинается с копии корня

Сложность:

    Время: O(h), где h — глубина изменяемого узла
    Память: O(h) на операцию (только путь от корня до узла)

Преимущество: обеспечивает полную персистентность

 4.3. Метод «Толстых узлов» (Fat Nodes)

    Подходит для Pointer-machine модели

Идея: каждый узел хранит массив версий своих состояний
Структура узла:

```
struct FatNode {
    struct Version {
        int version_id;      // номер версии, с которой актуально изменение
        int value;           // значение/данные узла
        FatNode* left;       // указатели на потомков (для этой версии)
        FatNode* right;
    } versions[MAX_VERSIONS]; // ограниченный массив изменений
};
```

Операции:

    При чтении: бинарный поиск по version_id → O(log t), где t — число изменений узла

    При записи в «тонкий» узел (есть место в массиве): добавляем новую версию → O(1)

    При переполнении: копируем узел + «вшиваем» в структуру (как в Path Copying)

Преимущества:

    Амортизированная сложность изменения: O(1)
    Обеспечивает частичную персистентность (можно расширить до полной с деревьями версий)

Недостатки:

    Накладные расходы на поиск версии
    Ограниченное число хранимых изменений (фиксированный размер массива)

5. Примеры персистентных структур

 Персистентный стек (на связном списке)

Операции:

    push(x, i) — вставка элемента x в версию i → создаёт версию j
    pop(i) — извлечение из версии i → создаёт версию k

Сложность:

    Время: O(1) на операцию (копируется только голова списка)
    Память: O(1) на операцию (новый узел + указатель)

 Персистентная очередь на двух стеках

Классическая идея:

    Два стека: s1 (вход), s2 (выход)
    enqueue(x): push в s1
    dequeue(): если s2 пуст — перелить всё из s1 в s2 (разворот порядка), затем pop из s2

Проблема: в эфемерной реализации амортизация O(1), но в персистентной — амортизация не сохраняется, т.к. старые версии должны оставаться доступными.

Решение: существуют реализации на 4–6 персистентных стеках с честным O(1) на операцию.

6. Модели реализации структур данных

RAM
	
    Линейная память с индексацией по адресу
	
    Удобен для массивов, но сложно сделать персистентным без копирования всего массива
Pointer-machine
	
    Узлы с ограниченной памятью и указателями на другие узлы
	
    Идеальна для персистентности: легко применять Path Copying и Fat Nodes

## Билет 52 Пространнственные деревья (а вдруг кого устно спросят)

1. Основные виды пространственных деревьев

Q-дерево (Quadtree, дерево квадрантов)

Определение:

    Используется для хранения данных, распределённых на плоскости
    НЕ сбалансировано
    Каждый узел имеет 0 или 4 потомка
    Каждый узел соответствует прямоугольнику, дочерние — квадрантам

Структура узла:

```
struct Rectangle {
    double x1, y1, x2, y2;
};

struct QuadTreeNode {
    Rectangle area;              // прямоугольник узла
    List<ValueType> data;        // данные в узле
    QuadTreeNode* quadrants[4];  // 4 потомка
};
```

Макропараметры:

    Прямоугольник корня
    maxElementsPerNode — критерий дробления узла
    Функция isInRect() — проверка вхождения объекта

Алгоритм вставки:

    Если есть потомки — делегировать вставку им
    Если нет потомков — вставить в текущий узел
    Если data.size > maxElementsPerNode — создать 4 дочерних узла и перераспределить все элементы

Алгоритм поиска по области:

```
List<ValueType> findValuesInRect(QuadTreeNode node, Rectangle rect) {
    List<ValueType> result;
    // Добавить элементы текущего узла
    for (el in node.data)
        if (isInRect(el, rect))
            result.add(el);
    // Рекурсивно проверить потомков
    if (node.quadrants != null)
        for (i from 0 to 3)
            if (intersect(rect, node.quadrants[i].area))
                result.addAll(findValuesInRect(node.quadrants[i], rect));
    return result;
}
```

Применение:

    Представление изображений
    Поиск коллизий в играх
    Индексация таблиц (Excel)
    Кластеризация данных

Octree (дерево октантов)
Определение:

    Используется для трёхмерного пространства
    Каждый узел имеет 0 или 8 потомков
    Соответствует параллелепипеду, дочерние — октантам

Применение:

    3D-графика
    Постеризация изображений (цвет = 3 координаты RGB)
    Физические симуляции в 3D

Постеризация через Octree:

    Все цвета изображения помещаются в октодерево
    Постепенное отсечение листьев
    Занесение среднего значения в родителя
    Результат — сокращение количества цветов

R-дерево (дерево прямоугольников)
Определение:

    Структура похожа на B-дерево
    Каждому узлу соответствует несколько прямоугольников
    Дочерние узлы содержат прямоугольники, полностью лежащие внутри родительского
    Сбалансировано

Применение:

    Поиск объектов на карте
    Индексы в базах данных
    Пространственные запросы

K-d дерево (k-мерное дерево)
Определение:

    Бинарное дерево
    Хранит точки в k-мерном пространстве
    Каждый узел кодирует разбиение пространства (k-1)-мерным гиперкубом
    Сбалансировано

Применение:

    Кластеризация данных
    Поиск ближайших соседей
    Многомерные индексы в БД

2. Области применения пространственных деревьев

    Анализ данных: кластеризация, поиск ближайших соседей
    Обработка изображений: представление, сжатие
    Поиск по диапазону: все пространственные деревья
    Индексы баз данных: R-дерево, K-d дерево
    Физические симуляции: поиск коллизий, гравитация
    Игры: оптимизация проверок столкновений  

3. Подбор макропараметров для Q-дерева

Выбор maxElementsPerNode:

    Зависит от стоимости isInRect()
    Зависит от сложности попарного сравнения объектов
    Экспериментально: для 1500 окружностей оптимально 4–16

Выбор прямоугольника корня:

    Центр тяжести прямоугольника ≈ центру тяжести совокупности объектов
    Размеры должны соответствовать разбросу объектов
    Неправильный выбор → все элементы в одном квадранте → деградация до O(n)

Функция isInRect():

    Не обязана быть абсолютно точной
    Главное: гарантированно возвращать false, если объект не входит
    Можно использовать грубую проверку для скорости

4. Пример: симуляция гравитации через Q-дерево

Задача: рассчитать изменение скорости и координат N объектов за время dt.

Наивный подход: O(N²) — рассмотреть каждую пару объектов.
Оптимизация через Q-дерево:

    Каждый узел хранит:
        Список объектов
        Центр масс поддерева
        Суммарную массу поддерева

    При вычислении силы гравитации:
        Далёкие элементы заменяются средним значением узла
        Близкие учитываются по отдельности

    Сложность: O(N log N) вместо O(N²)
